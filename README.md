# MAX-бот диспетчерской

Бот в мессенджере MAX: принимает заявки о технических проблемах (корпус, кабинет, описание), сам определяет категорию и сохраняет заявки в БД.

## Запуск

```bash
uv sync
cp .env.example .env        # вписать MAX_BOT_TOKEN от @Masterbot
uv run python -m app.bot    # polling, локально
```

Если у бота настроены webhook-подписки, polling не будет получать события. Их нужно удалить.

## На сервере

Docker Compose: бот через webhook, дашборд и HTTPS (Caddy). Пошагово — [deploy/README.md](deploy/README.md).

## Специалисты

Специалист — сотрудник с номером телефона и направлениями. Направления — это категории заявок из `config/org.yaml`. Пока нет админки на дашборде, специалистов заводят командой:

```bash
uv run python -m scripts.staff add "Иван Петров" +79001234567 network 1c
uv run python -m scripts.staff list
uv run python -m scripts.staff directions 3 network computers
uv run python -m scripts.staff deactivate 3
```

Специалист пишет боту `/staff` и нажимает «Поделиться номером». Бот принимает только собственный контакт пользователя, пересланный чужой не подойдёт, и находит специалиста по номеру. После входа специалист на линии: новые заявки его направлений приходят ему в личные сообщения с кнопками «Взять», «Готово» и остальными. В меню есть кнопки «Выйти на линию» / «Уйти с линии», «Заявки моих направлений» и «Все активные заявки».

Карточка заявки обновляется везде, где она лежит: в чате диспетчерской и в личке у всех специалистов.

## Доступ только для сотрудников

Если в `.env` задан `STAFF_CHAT_ID`, ботом могут пользоваться только участники этого чата (например, «Сотрудники»). Это касается и подачи заявок, и входа специалистов. Бот должен быть **администратором** этого чата: только так MAX показывает ему участников. Результат проверки бот запоминает на 10 минут. Если человека удалили из чата, доступ закрывается сразу, и специалиста снимает с линии. Если MAX не ответил на проверку, бот доступ не даёт.

ID чата бот присылает в личку тому, кто его добавил. Пустой `STAFF_CHAT_ID` — проверка выключена.

## Дашборд руководства

```bash
uv run python -m app.dashboard --db data/demo.db   # на демо-данных
uv run python -m app.dashboard                     # на рабочей БД бота
```

Откройте http://localhost:8000. Пока дашборд слушает только localhost. Наружу его можно открыть только через HTTPS: cookie сессии иначе идёт открытым текстом.

**Вход** — по коду из бота: вводите номер телефона, бот присылает 6-значный код в личку MAX. Код действует 5 минут, даётся 5 попыток, новый можно запросить через минуту. Войти может только сотрудник, который один раз написал боту `/staff`. Если задан `STAFF_CHAT_ID`, сотрудник ещё должен состоять в чате «Сотрудники». Демо-база (`--db data/demo.db`) открывается без входа и только для просмотра.

**Роли** (права проверяет сервер):

| | Обзор (аналитика) | Заявки | Взять, закрыть, вернуть, отменить, сменить категорию | Назначить, править, срок, приоритет | Категории | Сотрудники |
|---|---|---|---|---|---|---|
| Руководство | ✓ | все (без имён заявителей) | | | | |
| Специалист | | открытые — все; закрытые — своих направлений и взятые им | ✓ | | | |
| Диспетчер | ✓ | все | ✓ | ✓ | ✓ | |
| Администратор | ✓ | все | ✓ | ✓ | ✓ | ✓ |

Специалист не подаёт заявки — только выполняет (в боте у него нет «Новой заявки»). **Время выполнения** считается от назначения исполнителя («Взять» или назначение диспетчером) до «Готово»; время от подачи до взятия — отдельный показатель «Время до взятия».

**Сроки и приоритет.** У каждой заявки есть срок: при создании — норматив категории. Диспетчер может сдвинуть его (+1 день, +3 дня, +неделя), назначить дату или вернуть к нормативу; исполнитель получает уведомление. Просрочка считается от срока. Приоритет: срочный, высокий, обычный, низкий — срочные идут первыми в списках и помечены в карточке. Все изменения видны в истории заявки.

**Категории** хранятся в базе; ими управляет диспетчер в разделе «Категории» (название, норматив, ключевые слова для автоопределения). `config/org.yaml` задаёт только начальный набор при первом запуске.

**Первый вход сотрудника.** На странице входа и в разделе «Сотрудники» («Пригласить») есть ссылка `https://max.ru/<бот>?start=staff`: она открывает бота и сразу предлагает поделиться номером. Пока сотрудник этого не сделал, код входа ему не придёт.

Первого администратора назначают командой: `uv run python -m scripts.staff role ID admin`. Дальше администратор управляет сотрудниками в разделе «Сотрудники». Удаление сотрудника с историей заявок только отключает его, чтобы не потерять аналитику. При смене номера или отключении сотрудника все его сессии завершаются.

## Структура

| Путь | Что там |
|---|---|
| `config/org.yaml` | всё про организацию: корпуса, категории с ключевыми словами и нормативами, тексты бота |
| `app/config.py` | загрузка `.env` и YAML с проверкой |
| `app/models.py` | таблицы `requests`, `assignees`, `categories`, `status_log`; статусы и допустимые переходы |
| `app/repo.py` | создание заявки и смена статуса (только здесь, не в хендлерах) |
| `app/categorizer.py` | автоопределение категории по ключевым словам |
| `app/bot/` | хендлеры MAX, FSM, клавиатуры; `dispatch.py` — карточки, `staff_menu.py` — меню специалиста |
| `app/staff.py` | специалисты: учёт, вход по номеру, линия, выборки |
| `app/stats.py` | расчёт метрик для дашборда |
| `app/auth.py` | вход по коду из MAX, сессии, права ролей |
| `app/actions.py` | действия с заявками из веба с обновлением карточек в MAX |
| `app/dashboard/` | веб-интерфейс: FastAPI (`web.py`), страницы входа и приложения, `app.js`, `app.css`, логотип |
| `migrations/` | миграции Alembic |
| `scripts/seed_demo.py` | генератор демо-БД |
| `scripts/staff.py` | управление специалистами из командной строки |

## Команды бота

- `/start` — приветствие и меню
- `/new` — новая заявка
- `/my` — мои активные заявки
- `/cancel` — отменить заполнение
- `/staff` — вход для специалистов и их меню

## Миграции базы (Alembic)

Схема создаётся и обновляется миграциями из `migrations/`: бот и дашборд сами выполняют `upgrade head` при запуске.

```bash
uv run alembic revision --autogenerate -m "что изменилось"   # после правки app/models.py
uv run alembic upgrade head                                    # вручную, если нужно
uv run alembic current                                         # текущая версия базы
```

Тест `tests/test_migrations.py` падает, если модели поменяли, а миграцию не создали. База, созданная до Alembic, не запустится сама: если её схема актуальна, отметьте это командой `uv run alembic stamp head`.

## Переход на PostgreSQL

Поменять `DATABASE_URL` на `postgresql+asyncpg://…`, установить `asyncpg` и выполнить `uv run alembic upgrade head`.
