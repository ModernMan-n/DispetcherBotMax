# MAX-бот диспетчерской

Бот в мессенджере MAX: принимает заявки о технических проблемах (корпус, кабинет, описание), сам определяет категорию и сохраняет заявки в БД.

## Запуск

```bash
uv sync
cp .env.example .env        # вписать MAX_BOT_TOKEN от @Masterbot
uv run python -m app.bot    # polling, локально
```

Если у бота настроены webhook-подписки, polling не будет получать события. Их нужно удалить.

## Специалисты

Специалист — сотрудник с номером телефона и направлениями. Направления — это категории заявок из `config/org.yaml`. Пока нет админки на дашборде, специалистов заводят командой:

```bash
uv run python -m scripts.staff add "Иван Петров" +79001234567 network 1c
uv run python -m scripts.staff list
uv run python -m scripts.staff directions 3 network computers
uv run python -m scripts.staff deactivate 3
```

Специалист пишет боту `/staff` и нажимает «Поделиться номером». Бот принимает только собственный контакт пользователя, пересланный чужой не подойдёт, и находит специалиста по номеру. После входа специалист на линии: новые заявки его направлений приходят ему в личные сообщения с кнопками «Взять», «Готово» и остальными. В меню есть кнопки «Выйти на линию» / «Уйти с линии», «Заявки моих направлений» и «Все активные заявки».

Карточка заявки обновляется везде, где она лежит: в чате диспетчерской и в личке у всех специалистов.

## Доступ только для сотрудников

Если в `.env` задан `STAFF_CHAT_ID`, ботом могут пользоваться только участники этого чата (например, «Сотрудники»). Это касается и подачи заявок, и входа специалистов. Бот должен быть **администратором** этого чата: только так MAX показывает ему участников. Результат проверки бот запоминает на 10 минут. Если человека удалили из чата, доступ закрывается сразу, и специалиста снимает с линии. Если MAX не ответил на проверку, бот доступ не даёт.

ID чата бот присылает в личку тому, кто его добавил. Пустой `STAFF_CHAT_ID` — проверка выключена.

## Дашборд руководства

```bash
uv run python -m app.dashboard --db data/demo.db   # на демо-данных
uv run python -m app.dashboard                     # на рабочей БД бота
```

Откройте http://localhost:8000. Дашборд слушает только localhost: авторизации пока нет, поэтому открывать его наружу нельзя. Данные заявителей (имена, ID) на дашборд не выводятся.

## Тесты и демо-данные

```bash
uv run pytest
uv run python -m scripts.seed_demo   # data/demo.db: ~300 вымышленных заявок для дашборда
```

## Структура

| Путь | Что там |
|---|---|
| `config/org.yaml` | всё про организацию: корпуса, категории с ключевыми словами и нормативами, тексты бота |
| `app/config.py` | загрузка `.env` и YAML с проверкой |
| `app/models.py` | таблицы `requests`, `assignees`, `categories`, `status_log`; статусы и допустимые переходы |
| `app/repo.py` | создание заявки и смена статуса (только здесь, не в хендлерах) |
| `app/categorizer.py` | автоопределение категории по ключевым словам |
| `app/bot/` | хендлеры MAX, FSM, клавиатуры; `dispatch.py` — карточки, `staff_menu.py` — меню специалиста |
| `app/staff.py` | специалисты: учёт, вход по номеру, линия, выборки |
| `app/stats.py` | расчёт метрик для дашборда |
| `app/dashboard/` | дашборд: FastAPI и одна HTML-страница, графики на SVG без внешних библиотек |
| `scripts/seed_demo.py` | генератор демо-БД |
| `scripts/staff.py` | управление специалистами из командной строки |

## Команды бота

- `/start` — приветствие и меню
- `/new` — новая заявка
- `/my` — мои активные заявки
- `/cancel` — отменить заполнение
- `/staff` — вход для специалистов и их меню

## Переход на PostgreSQL

Достаточно поменять `DATABASE_URL` на `postgresql+asyncpg://…` и установить `asyncpg`. Перед этим нужно заменить `create_all` на миграции Alembic.
